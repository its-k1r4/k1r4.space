Why a Kanban Board

A kanban board looks simple — columns of cards you drag around — and that is exactly why it is a good exercise. Almost every part of front-end development shows up in it: a data model, rendering from state, event handling, the browser's drag-and-drop API, and persistence. You can build the whole thing in one HTML file, and the version in this tutorial is about 500 lines of vanilla JavaScript.

You need to be comfortable with document.createElement, template literals, and array methods like find and splice. Everything else is explained as we go.

Step 1: The Data Model

The board is four columns, each holding an array of card objects. Everything the board needs to draw itself lives in one object, boardData, keyed by column id. This is the single source of truth: you change the data, then re-render. You never edit the DOM directly to move a card.

JavaScriptconst COLUMNS = [
  { id: 'todo',     title: 'To Do',       color: '#026aa7' },
  { id: 'progress', title: 'In Progress', color: '#0079bf' },
  { id: 'review',   title: 'In Review',   color: '#525870' },
  { id: 'done',     title: 'Done',        color: '#0065ff' }
];

let boardData = {};

function loadData() {
  const saved = localStorage.getItem('kanbanBoard');
  if (saved) {
    boardData = JSON.parse(saved);
  } else {
    boardData = {};
    COLUMNS.forEach(col => { boardData[col.id] = []; });
  }
}

function saveData() {
  localStorage.setItem('kanbanBoard', JSON.stringify(boardData));
}

Every card is a plain object with a stable id, a title, an optional description, tags, and an ISO timestamp:

JavaScript{
  id: 'card_1728518400000_x7f2k1pqa',
  title: 'Write the README',
  desc: 'Cover the data model and the drag-and-drop step.',
  tags: ['docs', 'feature'],
  created: '2026-10-10T23:20:00.000Z'
}

The id is generated once and never changes, which matters later: drag and drop moves cards by id, not by position in the DOM.

Step 2: Rendering Columns and Cards

Rendering walks the columns, builds each one as a string of HTML, and replaces the board's contents in a single assignment. The card list of each column carries the drag events, and a button at the bottom of the column adds a card to it:

JavaScriptfunction renderBoard() {
  const board = document.getElementById('board');
  board.innerHTML = '';

  COLUMNS.forEach(col => {
    const column = document.createElement('div');
    column.className = 'column';
    column.dataset.columnId = col.id;
    column.innerHTML = `
      <div class="column-header">
        <div class="column-title">
          ${col.title} <span class="column-count">${boardData[col.id].length}</span>
        </div>
      </div>
      <div class="card-list" data-column="${col.id}"
           ondragover="handleDragOver(event)" ondrop="handleDrop(event)"
           ondragenter="handleDragEnter(event)" ondragleave="handleDragLeave(event)">
        ${boardData[col.id].map(card => renderCard(card)).join('')}
      </div>
      <button class="add-card-btn" onclick="openNewCard('${col.id}')">+ Add a card</button>
    `;
    board.appendChild(column);
  });
  updateStats();
}

Escape everything the user typed. Card titles and descriptions go into the page, so they go through one helper first. Setting textContent and reading back innerHTML is the shortest correct escape in vanilla JS:

JavaScriptfunction escapeHtml(text) {
  const div = document.createElement('div');
  div.textContent = text;
  return div.innerHTML;
}

Tags are rendered as coloured pills, with the colour chosen by tag name — bug red, urgent orange, enhancement green, anything else blue. A card is draggable="true" and carries its id in a data attribute, which is how the drag handlers know what moved.

Step 3: Adding and Editing Cards

One modal does both jobs. A single pair of variables — editingCard and editingColumn — decides whether saving creates a new card or updates an existing one, so there is no duplicated form code:

JavaScriptfunction saveCard() {
  const title = document.getElementById('cardTitle').value.trim();
  if (!title) return;                       // a card needs a title

  const desc = document.getElementById('cardDesc').value.trim();
  const tags = document.getElementById('cardTags').value
    .split(',').map(t => t.trim()).filter(Boolean);

  if (editingCard) {
    editingCard.title = title;
    editingCard.desc = desc;
    editingCard.tags = tags;
    editingCard.edited = new Date().toISOString();
  } else {
    boardData[editingColumn].push({
      id: generateId(), title, desc, tags,
      created: new Date().toISOString()
    });
  }

  saveData();      // write to LocalStorage
  renderBoard();   // draw the new state
  closeModal();
}

function generateId() {
  return 'card_' + Date.now() + '_' + Math.random().toString(36).substr(2, 9);
}

Notice the rhythm of every mutation in the board: change boardData, call saveData(), call renderBoard(). Deleting a card and clearing the board follow the same three lines.

Step 4: Drag and Drop

The HTML5 drag-and-drop API needs three things: draggable="true" on the card, a dragstart handler that remembers which card is moving, and a drop target that calls preventDefault() on both dragover and drop. Without the dragover preventDefault the drop event never fires at all — the browser thinks the element is not a drop zone.

JavaScriptlet draggedCard = null;

function handleDragStart(e) {
  draggedCard = e.target;
  e.target.classList.add('dragging');
  e.dataTransfer.effectAllowed = 'move';
}

function handleDragOver(e) {
  e.preventDefault();
  e.dataTransfer.dropEffect = 'move';
}

function handleDrop(e) {
  e.preventDefault();
  const targetColumn = e.currentTarget.dataset.column;
  if (!draggedCard) return;

  const cardId = draggedCard.dataset.cardId;
  const sourceColumn = findCardColumn(cardId);
  if (sourceColumn === null || sourceColumn === targetColumn) return;

  const cardIndex = boardData[sourceColumn].findIndex(c => c.id === cardId);
  if (cardIndex === -1) return;

  const [card] = boardData[sourceColumn].splice(cardIndex, 1);  // remove
  boardData[targetColumn].push(card);                           // insert
  saveData();
  renderBoard();
  draggedCard = null;
}

function findCardColumn(cardId) {
  for (const [colId, cards] of Object.entries(boardData)) {
    if (cards.find(c => c.id === cardId)) return colId;
  }
  return null;
}

A gotcha worth knowing. The board also tries to draw a dashed placeholder while you hover over a column, by appending a .drop-indicator element in the dragenter handler. As written, that handler runs on the .card-list element but looks for a child with list.querySelector('.card-list') — and an element is not a descendant of itself, so the lookup returns null and the handler throws before the placeholder is added. The drag, drop and reordering all still work; only the placeholder never appears. Appending the indicator to list directly fixes it.

Step 5: Persistence, Import and Export

localStorage keeps the board between visits, but it belongs to one browser on one machine. Export writes the same JSON to a file the user owns, and import reads it back through a hidden <input type="file">:

JavaScriptfunction exportData() {
  const blob = new Blob([JSON.stringify(boardData, null, 2)], { type: 'application/json' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = 'kanban-board-export.json';
  a.click();
  URL.revokeObjectURL(url);
}

function handleImport(event) {
  const file = event.target.files[0];
  if (!file) return;
  const reader = new FileReader();
  reader.onload = (e) => {
    try {
      boardData = JSON.parse(e.target.result);
      saveData();
      renderBoard();
    } catch (err) {
      alert('Invalid file format.');
    }
  };
  reader.readAsText(file);
  event.target.value = '';   // so the same file can be chosen twice
}

And the stats bar is just arithmetic over the same object: total cards, cards in the done column, and the percentage between them.

What We Learned

Building a kanban board teaches a handful of ideas that transfer to almost any app:

  • State first — the board is data; the DOM is a drawing of it. Move data, then re-render.
  • Stable ids — cards move by id, never by index, so reordering cannot lose one.
  • preventDefault on dragover — the single most common reason a drop handler "doesn't work".
  • Escape user input — card text is untrusted; escape it before it reaches the page.
  • Own your data — LocalStorage plus a JSON export means the user's board is theirs, not a server's.
